# Устройство

```text
          Telegram
             |
   подписанные данные + сообщения бота
             |
        +----------+       отдаёт файлы приложения
        | pustol-  |---------------------------+
        |   api    |                           |
        +----+-----+                           v
             |                           Mini App
      +------+------+                 (Next.js, статика)
      |             |
+-----v----+  +-----v--------+
| pustol-  |  | pustol-      |
|   db     |  |  telegram    |
+-----+----+  +--------------+
      |
+-----v------+        +-------------------+
| PostgreSQL |        |  pustol-domain    |
+------------+        | (правила, без I/O)|
                      +-------------------+
```

| Часть | За что отвечает |
| --- | --- |
| `crates/pustol-domain` | Все правила: раздача столов, доступность, часы работы, что считается допустимой конфигурацией. Без I/O и без часов, поэтому проверяется исчерпывающе. |
| `crates/pustol-db` | Транзакции, а значит и инварианты, которые может держать только транзакция. |
| `crates/pustol-telegram` | Доказательство, что запрос действительно от Telegram, сессии, разговор с ботом в обе стороны. |
| `crates/pustol-api` | HTTP, аутентификация, работник очереди, чтение сообщений боту и файлы приложения. Намеренно тонкий. |
| `web` | Mini App: Next.js 16, React 19. Каждый экран пререндерится, поэтому приложение — это просто файлы. |
| `migrations` | Схема, применяется на старте и тестами. |

## Один ответ на вопрос о доступности

Любой вопрос о доступности — выбор времени у гостя, форма брони у персонала, пересадка после закрытия
стола — вызывает **одну и ту же** функцию в `pustol-domain`.

Взятие брони идёт дальше: оно запрашивает тот же список времён, что и выбор времени у гостя, и
требует, чтобы выбранное время вернулось свободным.

## Два замка, две работы

- Консультативная блокировка на бар выстраивает в очередь «прочитать, решить, записать», поэтому
  обычный случай проходит с первой попытки. Разные бары не ждут друг друга.
- Ограничение `EXCLUDE` в базе делает необычный случай *безопасным*. Блокировка — про скорость,
  ограничение — про истину.

В схеме второе выглядит так:

```sql
exclude using gist (table_id with =, occupies with &&)
  where (status <> 'cancelled' and table_id is not null)
```

Один стол, одна компания, один момент. Отменённые брони и брони без стола не занимают ничего.

## Очередь сообщений

Решение отправить — транзакционное, отправка — нет. Решение записывается в таблицу, а работник
доставляет его потом, по двадцать штук за раз, по пять одновременно. Взятое сообщение на пять минут
уходит из очереди, поэтому второй работник не отправит его, пока первый ждёт ответа Telegram. Каждый
вызов Telegram ограничен двадцатью секундами.

Ошибки разбираются по тому, может ли повтор вообще помочь: заблокированный бот запоминается и больше
не повторяется; ограничение частоты ждёт ровно столько, сколько попросил Telegram, и не считается
попыткой; отклонённый по существу запрос не повторяется; сбой сети ждёт 2, 4, 8… минут, не больше
часа, а после восьми попыток — около трёх часов — сообщение бросают, чтобы оно не держало очередь.

Сообщения, которые уже никому не помогут, снимаются с очереди, не дожидаясь попыток: уведомление об
отмене или переносе вечера, который закончился, и напоминание о брони, которую отменили или которая
уже началась. Напоминание не уходит и компании, оставшейся без стола. Сообщение, которое выбрал
персонал, по времени не снимается никогда.

Итог доставки — отправлено, отложено, брошено — записывается только в ту строку, которую работник
взял, и только если её с тех пор не переписали. Перенос брони, пока её напоминание отправляется,
переписывает строку, и итог старой отправки новое напоминание уже не трогает.

## Бот слушает

Процесс сам забирает то, что пишут боту, долгим опросом Telegram. Кнопка «Не смогу прийти» под
напоминанием отменяет бронь её владельца, `/start` получает ответ, остальные сообщения — ответ, что
здесь не читают, и контакт бара. Опрос прерывается остановкой процесса только пока ждёт; начатый
ответ доводится до конца.

## Безопасность в одном абзаце

Первый запрос несёт подписанные Telegram данные, они проверяются токеном бота и живут час; в обмен
сервер выдаёт сессию на сутки, подписанную своим ключом. Права даёт числовой аккаунт, а не ник, и они
читаются из базы на каждом запросе. Токен бота не попадает ни в лог, ни в текст ошибки, который
хранится в очереди, а ошибка сервера не отдаёт наружу ничего, кроме кода. Каждый ответ запрещает
угадывать тип файла, отправлять адрес страницы и показывать приложение в чужой рамке. Row level
security включена без единой политики, а роли, которые управляемый PostgreSQL выставляет в интернет,
лишены прав полностью, — так что записать бронь можно только через API. Образ работает не от root.

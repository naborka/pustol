# Запуск

Нужны три вещи: машина, база PostgreSQL 17 и бот в Telegram.

Версии: **Rust 1.96**, **PostgreSQL 17**, **Node 20.9+**.

## 1. Бот в Telegram

В Telegram напишите [@BotFather](https://t.me/BotFather):

1. `/newbot` — вы получите токен вида `123456:AA...`. Держите его в секрете.
2. `/newapp` (или *Bot Settings → Menu Button*) — укажите адрес, по которому будет отдаваться
   веб-приложение.

Ещё понадобится ваш собственный ник в Telegram: он станет первым админом бара.

## 2. База данных

Скрипт достаёт настоящий PostgreSQL 17 в `.tools/pg`. Без root, без контейнера, без пакетного
менеджера:

```bash
scripts/pg.sh install
scripts/pg.sh start
```

Он печатает строку подключения. Другие команды: `stop`, `status`, `reset`, `psql`, `url`.

Подойдёт любой PostgreSQL 17; скрипт нужен, чтобы тестам было с чем разговаривать.

## 3. Создать бар

```bash
export DATABASE_URL="$(scripts/pg.sh url)"
export TELEGRAM_BOT_TOKEN=123456:your-bot-token
export TELEGRAM_ADMIN_USERNAME=your_telegram_username

cargo run -p pustol-api --bin seed
```

Применяется схема и создаётся один бар: неделя, зал из пятнадцати столов в трёх зонах и вы как первый
админ. Второй запуск ничего не сделает: он сообщит про уже существующий бар и остановится.

Всё созданное потом правится во вкладке настроек.

## 4. Запустить

Во время работы над проектом — два процесса:

```bash
cargo run -p pustol-api                # API и работник очереди, на :8080
cd web && npm install && npm run dev   # приложение на :3000
```

Веб-приложение проксирует `/api` на API, поэтому браузер всегда обращается к одному адресу и CORS
настраивать не нужно.

## 5. Запустить так, как оно поставляется

Один процесс, один адрес, без Node:

```bash
cd web && npm run build              # пишет в web/out
PUSTOL_ASSETS_DIR=web/out cargo run -p pustol-api --release
```

API сам отдаёт файлы приложения. Один источник здесь — следствие того, что слушатель один, а не
правило проксирования, которое кому-то надо держать верным.

## Открыть вне Telegram

Нельзя, и это намеренно: без подписанных Telegram данных сервер отказывает в любом запросе.

Для локальной работы задайте `NEXT_PUBLIC_DEV_INIT_DATA` — настоящие подписанные данные. Получить их
может только владелец токена бота, и сервер проверяет их ровно так же, как у настоящего клиента:
это удобство, а не лазейка.

## Две вещи про строку подключения

- Миграции идут на старте и берут блокировку уровня сессии, поэтому подключение должно быть
  **прямым или в session-режиме**. Транзакционный пул может отдать снятие блокировки другому
  бэкенду, не тому, который её взял.
- `DATABASE_MAX_CONNECTIONS` считается **на процесс**. Два процесса умножают это число на два.
